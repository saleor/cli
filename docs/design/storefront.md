# Storefronts

The storefront module downloads [saleor/storefront](https://github.com/saleor/storefront) and connects it to one store. It provides `storefront create` and `storefront use` (`ensure` actions, each naming the store as `<env>`), and extends `init` with `--storefront`.

- **One active backend.** A storefront is connected to one store. `storefront use` switches the backend recorded in the local storefront's `.env`. It is offered in menus only inside a storefront; explicit calls accept `--dir`. It does not manage Cloud environments or hosted deployments. Its `.env` is the only record: a header line `# saleor: instance=<ref>` and the two keys the CLI owns. Nothing is written to the user's config or to a manifest.
- **`.env` from `.env.example`.** The template's README says to copy `.env.example` to `.env`, so the CLI does the same and sets its keys in place, uncommenting them if needed. Every other line is kept, in storefronts the CLI did not create too.
- **The template follows `main`,** as a tarball from GitHub, without history. A new storefront becomes its own git repository unless it sits inside one. If `.env.example` stops mentioning a key the CLI sets, it is set anyway and a warning says the template may have changed.
- **Warnings, not failures,** for everything after the `.env` is written: an unreachable or stopped store, a channel that does not exist (checked with the public `channel` query), missing git, failed install. Dependencies are installed automatically during creation and on retries.
- **Stores from any module.** Stores come from the instance sources Cloud and local contribute (see [command conventions](commands.md#stores-across-modules)), so this module imports neither.
- **The project folder** exists only when `init` makes it (`init --storefront`): the user asked for a project, so it gets a folder (`<project>/storefront`, one repository at its root). `storefront create` asked for a storefront only, so it makes just that, wherever it is run. There is no manifest yet: nothing reads one. When a command needs to find the folder (configurator, apps), it can recognize today's folders by their connected storefront.
- **Shared with the app template.** Downloading and unpacking, the git repository, `pnpm install` and `.env` editing are in core (`scaffold.ts`, `env-file.ts`), for the app template module.
